## Execution notes (001–005)

All five plans are executed. Where execution diverged from the plan text:

- **004**: the plan specified 210,000 PBKDF2 iterations. That count is above the
  workerd ceiling and made **every login and signup return HTTP 500** in
  production (`NotSupportedError: Pbkdf2 failed: iteration counts above 100000
  are not supported`). Measured against the deployed worker: 50000 ok, 100000
  ok, 200000 throws, 600000 throws. Shipped 100000, the highest accepted value,
  and added a test pinning the count at or below it. Because the iteration count
  is stored inside each hash, it can be raised without a migration if the
  platform lifts the cap. See commits `550a0a8` (probe) and `80568cc` (fix).
- **004**: the plan scoped security headers to "API responses" but the
  implementation landed them in `auth.ts` only, leaving the other 7 endpoints
  without them. Corrected in `362b861` with a shared `jsonResponse()` and a
  source-reading regression test.
- **005**: `insights()` also had to keep projecting `next3` from the last
  observed period when the average is a fallback, otherwise `next3` went empty
  for a user with exactly one logged period.
