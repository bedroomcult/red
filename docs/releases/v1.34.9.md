# Release v1.34.9 — Close-then-sync, part 2

**Tag:** `v1.34.9` · **Commits:** `7a2ae72`, `ddfee9d` · **Follows:** v1.34.8

## What changed

v1.34.8 converted LogSheet and the DaySheet quick-period toggle to
close-then-sync (sheet closes on tap, request runs behind it, failure
surfaces as a banner with one-tap retry). This release extends the same
pattern to every remaining sheet-level write:

| Component | Change |
|---|---|
| `DaySheet` extras | Symptom toggle, note save, dose, sex log now close-then-sync via `onSyncFail` |
| `BcPanel` | BC save/stop close first, sync behind |
| `EcPanel` | EC save/delete close first, sync behind |
| `OngoingPrompt` | Period-end confirm closes first, syncs behind |
| `Home` | Threads `onSyncFail` through to `OngoingPrompt` |
| `App` | Shared `syncFail` banner + retry already landed in v1.34.8, reused here |

## Why

Same root cause as v1.34.8: every sheet awaited the server echo before
closing, so a slow network held the UI hostage behind a spinner. Toggles
were already optimistic (local state first, rollback on error); these
paths now match: close instantly, reconcile when the echo lands.

## Failure surface

No sheet left to show an error in — so all failures route to the App-level
`syncFailed` banner with a `syncRetry` button. Retry re-runs the exact
request closure; a second failure re-arms the banner.

## What stayed blocking (deliberate)

- Account delete, data export (destructive / file download — trapping is correct)
- Onboarding saves (multi-step flow needs the echo before advancing)
- Login/signup (auth must confirm before navigating)

## Verify

1. Install `red-1.34.9.apk`
2. Log a symptom, dose, BC change, EC event — sheet should close instantly
3. Airplane mode → save → banner appears → reconnect → retry succeeds
