## Summary

The copy is in better shape than a typical AI-written product. It names the actor,
avoids buzzwords, uses specific numbers where real ones exist, and the
pregnancy-chance wording is carefully hedged for safety. Most findings are
type and punctuation consistency, not voice.

Two findings are worth fixing on their own merits: F-01 and F-05.

## Findings

### F-01 — Loading ellipsis uses a single character (HIGH, R-02)

`loading: 'Memuat…'` uses the ellipsis character `…`, as does `bcHint`
(`placebo 2–4.` uses an en dash too).

Same family as the em dash ban: the typographic dash and ellipsis characters are
the mechanical-substitution tells. The rule bans `—` specifically; `…` and `–`
are the same habit and the same fix.

Fix: `Memuat...` and `placebo 2-4.`

Files: `src/i18n.ts` (`loading`, `bcHint`, `ecHint`, `ecDisrupted`)

### F-02 — En dash used as a range separator in 4 strings (HIGH, R-02)

`bcHint` `hari placebo 2–4`, `ecHint` `±7–10 hari`, `ecDisrupted` `21 hari setelah`,
`chanceBefore`/`chanceAfter` build day offsets.

An en dash between numbers is standard typography, and it is also what a model
emits by default when it writes a numeric range. Banning it outright would be
over-sterilizing, so the honest call is: keep the meaning, use the plain hyphen,
which is what the rest of this file already does elsewhere.

Fix: replace `–` with `-` in all numeric ranges.

Files: `src/i18n.ts`

### F-03 — Ellipsis in the note placeholder (MEDIUM, R-02)

`notePlaceholder: 'Tulis apa yang Anda rasakan…'` and
`passwordPlaceholder: 'Minimal 8 karakter'`.

Same as F-01. Fix: `Tulis apa yang Anda rasakan...`

Files: `src/i18n.ts` (`notePlaceholder`)

### F-04 — `Berhasil masuk. Selamat datang kembali.` is an AI-pleasing closer (MEDIUM, R-36)

`loginSuccess: 'Berhasil masuk. Selamat datang kembali.'` and
`signupSuccess: 'Akun berhasil dibuat. Selamat datang!'`

The first sentence is the real status. The second is a warm send-off that adds no
information, which is the generic-positive-conclusion pattern at string scale. A
login confirmation does not need to greet the user twice.

Fix: `Berhasil masuk.` and `Akun berhasil dibuat.`

Keep the second sentence only if the welcome is a deliberate product-voice choice.
It reads as chat, not product confirmation.

Files: `src/i18n.ts`

### F-05 — `Hentikan KB` and `Hapus` share a button with no confirmation (HIGH, C-2 / R-26)

`bcStop: 'Hentikan KB'` sits in the same `.btn danger` slot as plain `Hapus`, and
`bcStop` calls `DELETE /api/bc` immediately. Ending contraception is a
consequential action; a single tap with no confirmation reads the same as clearing
one day's note.

This is a copy-adjacent function finding, so it is listed here rather than acted on:
the label is accurate, the missing piece is a confirmation step.

Recommend: separate ticket, not a copy change. Flagging because the audit covers
the destructive-action vocabulary and the two verbs currently sit in one visual slot.

Files: `src/i18n.ts` (`bcStop`), `src/BcPanel.tsx`

### F-06 — `noLog: 'tanpa catatan = prediksi tetap kosong'` uses a bare equals sign (MEDIUM, R-02)

An `=` in prose is a shorthand tell. It reads as a code comment, not a sentence.

Fix: `tanpa catatan, prediksi tetap kosong.`

Files: `src/i18n.ts` (`noLog`)

### F-07 — Lowercase sentence starts in status strings (LOW, R-02)

`logged: 'tercatat'`, `bcTakenToday: 'sudah minum pil hari ini'`,
`ecNoHistory: 'belum ada catatan'`, `nothing: 'belum ada catatan'`,
`dayOngoing: 'belum ditandai selesai'`, `noLog` above.

These are used mid-sentence in most call sites, so lowercase is defensible there.
It fails where the string is the whole line, e.g. `bcTakenToday` in a checkbox
label and `nothing` as a card's only content.

Fix: capitalize only the strings rendered as a full sentence. Leave the inline ones
alone. Do not blanket-capitalize.

Files: `src/i18n.ts`

### F-08 — `homeOvSub: 'Masa paling subur dalam siklus Anda.'` is a superlative with no evidence (MEDIUM, R-16 / C-5)

The other phase subtitles state something actionable (`homeFertileSub` tells the
user what to do, `homePmsSub` names a symptom). This one asserts a peak. It is the
prediction restated as a fact, and the app elsewhere is careful to say the
ovulation day is an estimate.

Fix: `Perkiraan hari paling subur.` Keeps it a prediction, matching the care taken
in `dayOvulationValue` (`Perkiraan, bukan hasil tes.`).

Files: `src/i18n.ts` (`homeOvSub`), `src/Home.tsx`

### F-09 — `README.md` uses a spaced en dash in a payoff sentence (LOW, R-02)

`Predictions persist past expected date until confirmed.` is fine. The line
`BC regimen active → predictions suppressed (amber banner). EC within 60d → widened
window` uses `→` as prose connective in four bullets.

Arrows as prose connectives are the R-08 habit in text form. In a README they read
as notes-to-self, which is honest, but the four bullets would be clearer as full
sentences.

Fix: rewrite the four bullets as sentences. Optional.

Files: `README.md`

### F-10 — Reminder notification body is generic (LOW, R-16)

`notify.ts`: `title: 'Waktunya minum pil KB'`, `body: 'Jangan lupa minum pil hari ini.'`

The title carries the content. The body restates it. A notification body that adds
nothing is better replaced with something specific, or the body dropped.

This is a minor note: notification bodies often have room constraints, and a
two-line notification needs a body. Leave unless the title alone renders.

Files: `src/notify.ts`

## What NOT to change (checked and cleared)

These look like they could be findings but are correct as written:

- `chanceSafeNote`, `chanceAverageNote`, `chanceDisclaimer`. Multiple disclaimers
  stacked is normally a padding tell. Here each states a different real limit
  (population average, ovulation-day assumption, not-a-test), and the app is
  making a medical-adjacent claim. This is the one place where the repetition is
  load-bearing. Keep all three.
- `ecDisrupted` and `ecActiveHint`. Long and specific, with real numbers and a real
  action. Not slop.
- `bcHint`. Specific mechanism plus a real day range.
- The `day*` and `phase*` families. Consistent, specific, no filler.
- `disclaimer`. Correct scope, correct length.
- `chanceBelowOne: '<1%'`. Correct handling of a number that cannot be stated as a
  percentage.
- Home phase subtitles other than `homeOvSub`. Each says something a user can act on.
